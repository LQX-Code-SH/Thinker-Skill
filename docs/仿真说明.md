## 1. 定位与边界

仿真用于**不接真机时验证完整调用链**：Service / Action → `thinker_host` → `SkillRuntime` → `Step` → `BodyAPI` / `SensorAPI` → ROS 话题 → MuJoCo。技能代码、能力校验、租约、超时与错误信封都与真机一致，差异只在机型适配器的“话题层”。

三条边界：

1. **仿真只在 Jazzy 容器内跑。** 宿主机是 Humble，两者 DDS 能互相发现端点但数据面不通，详见 §8.2。
2. **平衡不归本框架管。** 半身模式依赖厂商 xmigcs 的 FSM（HBWALK）；`fixed_base:=true` 只用于机械臂调试，不是交付路径。
3. **仿真是验证环境，不是替代真机。** 接触、相机成像、手的触觉等与真机仍有差距，见 §10。

## 2. 架构

```
宿主机（Humble）
  └─ docker: thinker_sim（Jazzy，--network host --ipc host）
       ├─ xmigcs_sim            厂商运控 / FSM（半身模式）
       ├─ manip_sim mujoco_bridge
       │    ├─ 订阅 /{arm,waist,head,leg}/cmd、/cmd_ctrl、/hric/robot/fsm_state_cmd
       │    └─ 发布 /robot_state、/{arm,waist,head,leg}/status、/ob_camera_*、/manip/base_pose、手话题
       └─ thinker_host（THINKER_CONFIG_DIR=configs/sim）
            └─ robosim 适配器 → 复用 TienkungDexBody / TienkungDexSensor，只换话题层
```

| 组件 | 职责 | 入口 |
|---|---|---|
| `sim/robot_sim` | MuJoCo 场景、桥、遥控器、XMIGCS 集成（子模块） | `src/manip_sim/launch/sim.launch.py` |
| `robots/tienkung_dex/tienkung_dex_robot/robosim/` | robot_sim 话题 ↔ `BodyAPI` / `SensorAPI` | `create_adapter(backend="robosim")` |
| `configs/sim` | 仿真配置（backend、能力差异、技能参数） | `main.yaml` + `sim.yaml` |
| `tools/sim` | 容器封装、探针、自测、取流、位姿 | `container.sh` 等 |

两种启动模式：

| 模式 | 命令 | 基座 | 用途 |
|---|---|---|---|
| 机械臂调试 | `make sim-bridge` / `sim-bridge-bg` | `fixed_base:=true` | 没有运控时单独验手臂、相机、技能 |
| 半身 FSM | `make sim-fsm` / `sim-fsm-bg` | `fixed_base:=false` | 完整交付路径：吊带 → SWR → HBWALK |

## 3. 前置条件

- Docker 可用，本地已有镜像 `manip_local:v4`（可用 `IMAGE=` 覆盖）。
- 仓库子模块与资产已拉取：`make sim-init`（`robot_sim` + 选择性 LFS）。
- 首次使用先构建：`make sim-up` → `make sim-build`。构建产物在容器的 `/thinker/.colcon-sim/`，不进 git。
- 需要窗口时宿主机有 `DISPLAY`；无显示器用 `*-bg` 目标，日志在 `/tmp`。
- 容器默认 `ROS_DOMAIN_ID=42`，可用 `ROS_DOMAIN_ID=0 make sim-up` 覆盖。宿主机只有设置相同 domain 才能 `ros2 topic list`，但**仍然收不到数据**。

## 4. 快速开始

### 4.1 机械臂调试（无运控）

```bash
make sim-init                # 首次：子模块 + LFS 资产
make sim-up                  # 起容器 thinker_sim（--network host --ipc host）
make sim-build               # 容器内构建 robot_sim + Thinker-Skill

make sim-bridge-bg           # 后台起桥（钉基座、无窗口），日志 /tmp/sim_bridge.log
make sim-host-bg             # 后台起 thinker_host，日志 /tmp/thinker_host.log
make sim-logs                # 看两个日志尾部

make sim-selftest SIM_SKILL=look_down_table            # 进程内直接调技能
make sim-call SIM_SKILL=look_down_table SIM_PARAMS='{"pitch_deg": 45}'   # 走 Service
make sim-pose                # 打印 /manip/base_pose → x/y/z + yaw
make sim-image-view          # 浏览器看相机（见 §8）
```

### 4.2 半身 FSM（交付路径）

```bash
make sim-fsm-bg              # 起 FSM + 桥 + 遥控器链路，日志 /tmp/sim_fsm.log
make sim-host-bg
```

进入 HBWALK 的按键序列与真机一致（`run_fsm.sh` 会打印提示）：

```
gotoZERO  → STANDZERO
gotoSTART → SWR          # 遥控器长按 A（拨杆全中位）
gotoHBWALK→ HBWALK       # H 拨到右（h=-1）
```

有窗口时 `make sim-fsm` 会同时起 `teleop_gui`；无窗口（没有 GUI）或没有实体遥控器时，用代码发同一串按键：

```bash
docker exec -it thinker_sim bash -lc "
  source /thinker/tools/sim/env.sh; source /thinker/.colcon-sim/robot-install/setup.bash
  ros2 run manip_sim sim_remote --sequence hbwalk --publish-fsm"
```

吊带高度默认 `SIM_HANG_Z=1.0`（`Makefile`），等 SWR 期间机器人挂在吊带上；`hang_height` 过高会让腿够不到零位。

### 4.3 检查点

1. `docker ps` 能看到 `thinker_sim`。
2. `make sim-probe`：8 项全 `OK`、相机两路有帧，退出码 0。
3. `make sim-logs`：host 正常起服务、无 traceback。
4. `make sim-selftest`：打印 `skills: [...] skipped: [...]` 并返回 `state=success`；skipped 非空时先看 `capabilities.yaml` 与技能 `requires`。

## 5. 命令清单

| 命令 | 作用 | 备注 |
|---|---|---|
| `make sim-init` | 初始化子模块 + 拉取 `manip_description` 资产 | 仅首次/换机器 |
| `make sim-up` / `sim-down` | 起/停容器 | 起容器会先删除同名旧容器 |
| `make sim-build` | 容器内构建 robot_sim + Thinker-Skill | 产物 `/thinker/.colcon-sim/` |
| `make sim-bridge` / `-bg` | MuJoCo 桥，`fixed_base:=true` | 前台带窗口 |
| `make sim-fsm` / `-bg` | FSM + 桥 + 遥控器，`fixed_base:=false` | 半身模式 |
| `make sim-host` / `-bg` | 起 `thinker_host`（`configs/sim`） | 装/卸技能后需重启 |
| `make sim-probe` | 真机接口对齐检查 | 见 §4.3 |
| `make sim-selftest` | 进程内装配 host 后直接执行技能 | 不经过 ROS 通道 |
| `make sim-call` | 走 `/thinker/skill/<skill>/command` | 需要 host 已起 |
| `make sim-pose` | 读 `/manip/base_pose` 换算位姿 | `SIM_POSE_ARGS='--count 5'` |
| `make sim-image-view` | 网页相机取流 | `http://localhost:8090`，`SIM_VIEW_PORT` 可改 |
| `make sim-logs` | tail bridge / host 日志 | |
| `make sim-shell` | 进容器交互 shell | 已 source env |

初始位姿（世界系，米 / 度）：`SIM_INIT_X=4.0`、`SIM_INIT_Y=-2.60`、`SIM_INIT_YAW=180`（`Makefile` 默认），`SIM_INIT_Z` 留空表示用站姿反解高度。场景出生点约 `(4.73, -2.60)`，实际基座位姿以桥发布的 `/manip/base_pose` 为准。

## 6. 接口映射与能力差异

`configs/sim/sim.yaml` 设 `backend: robosim`，`create_adapter()` 走 `robots/tienkung_dex/tienkung_dex_robot/robosim/`。它复用真机的关节表、限位、IK 与手部映射，只替换命令/状态/相机这一层：

| 用途 | 真机 | 仿真 |
|---|---|---|
| 手臂命令 | `/arm/cmd` | `/arm/cmd`（对齐接口）+ `/arm/cmd_ctrl`（适配器在用） |
| 状态总成 | `/robot_state` | `/robot_state`（由 4 路 `status` + `/imu/status` 聚合，默认 100 Hz）+ `/{...}/status` |
| 头/腰命令 | `/head/cmd`、`/waist/cmd` | `/head/cmd`、`/waist/cmd`（对齐接口）+ `cmd_ctrl` |
| 头部符号 | URDF 低头为正 | MJCF 低头为负，`sim_mapping.yaml: head.pitch_sign` |
| 相机 | `/ob_camera_head/...` | 同名；内参取话题 `camera_info`（640×480），不用 `configs/robot.yaml` 的真机 K |
| 相机位姿 | URDF 正运动学 | 优先 `/ob_camera_head/pose`（pelvis 系） |
| 手 | 因时/强脑同名话题 | 因时默认，手 id 见 `sim_mapping.yaml` |
| FSM 状态 | 厂商节点 | 桥转发 `/manip/fsm_state`（`TRANSIENT_LOCAL`） |
| 基座位姿 | — | `/manip/base_pose`（`Float64MultiArray`：x,y,z,qw,qx,qy,qz） |

`/robot_state` 与 `/…/cmd` 的消息类型是 `ros2_bridge_msgs`。子模块里有一份按 dex.md 复制的定义（`sim/robot_sim/src/ros2_bridge_msgs`）；厂商 SDK 可用时应优先使用 SDK 的原始包，避免两份定义随版本漂移。

命令语义：`/…/cmd` 只区分 mode 0/1（位置 / 力位混合），都按 pos/spd/tor 执行；`cur`、`joint_ids` 与 mode 2/3/4/5 不模拟。HBWALK 下 `/leg/cmd` 会被忽略（腿归 FSM），`fixed_base` 调试时才接。

能力契约（`robots/tienkung_dex/capabilities.yaml: backend_variants.robosim`）在装配期做差集：

- 去掉：`body.base`、`sensor.audio_in`、`sensor.audio_out`、`sensor.pointcloud`、`sensor.imu`
- 相机只保留 1 路（`/ob_camera_head`，深度单位 mm）

因此 `requires` 里带 `body.base` 等能力的技能在仿真中会被跳过并出现在 `skipped`，这是预期行为，不是装配失败。

话题、增益、限值都在 `robots/tienkung_dex/resources/sim_mapping.yaml`，host 启动时读取，改完重启 host 即可，不需要重编。

## 7. 配置

```
configs/sim/main.yaml     includes: ../robot.yaml + sim.yaml
configs/sim/sim.yaml      model / backend / hand_variant / camera / 技能参数
configs/sim/errors.yaml   仿真侧错误模板覆盖（如需）
```

- 技能私有参数写在 `configs/sim/sim.yaml` 的 `skills.<name>` 段，host 通过 `ctx.cfg` 注入。
- robot_sim 侧接口开关在子模块的 `src/manip_sim/config/interfaces.yaml`：`sensors.cameras`、`sensors.lidar`、`hands`、分辨率与 fps。改完重新 `make sim-build`（`--symlink-install` 下多数配置直接生效）。
- 相机每帧离屏渲染，开查看器时把 `fps` 或分辨率压低，否则物理步进会变慢。
- 桥的 `--robot-state-hz`（默认 100）控制 `/robot_state` 频率，`--status-hz`（默认 400）控制原 `/…/status`；`--status-joints vendor` 会同时裁剪 `/robot_state`。
- 接厂商 SDK 时注意同名包遮蔽：当前 `env.sh` 先 source SDK、launch 再 source robot-install，后者会覆盖 SDK 的 `ros2_bridge_msgs`；需要以 SDK 为准时，给子模块里的副本加 `COLCON_IGNORE` 或从工作区移除。
- `detect_object` 的权重路径相对仓库：`skills/perception/detect_object/skill/weights/`（`configs/sim/sim.yaml: model_path`）。

## 8. 相机取流与查看

### 8.1 网页视图（推荐）

```bash
make sim-image-view          # SIM_VIEW_PORT=8091 可换端口
```

浏览器打开 `http://localhost:8090`：下拉框列出所有 `Image` / `CompressedImage` 话题，可切话题、帧率、JPEG 画质；深度图自动归一化。另有单帧接口 `/snapshot?topic=...` 便于脚本核对。

### 8.2 为什么宿主机 rqt 打不开相机

- 宿主机是 Humble，容器是 Jazzy。DDS **发现**兼容（`ros2 topic list` 能看到话题、`Publisher count: 1`），但**数据面**不通。实测 Jazzy 发布 `std_msgs/String`、Humble 订阅，6 秒 0 帧；相机同样 0 帧。
- 相机发布端是 **BEST_EFFORT**（与真机 Orbbec 一致）。即使同版本，RELIABLE 订阅也会被判定 `incompatible QoS ... Last incompatible policy: RELIABILITY`，rqt_image_view 需选 Best effort。
- rqt_topic 还会对 `inspire_hand_msgs`/`bodyctrl_msgs` 报 `can not get message class`，随后在排序时对 `None` 比较崩溃——这是宿主机没装这些消息包导致的，与相机无关。

结论：查看/录制都在容器内做。宿主 rqt 只能看到话题名（Topic Monitor 还会因缺消息包报错）；要在宿主看画面，走 §8.1 的 HTTP 视图或自己加转发。

### 8.3 大图必须带 SHM profile

默认 Fast DDS 的 SHM 段仅 512 KB，而 640×480 rgb8 一帧 921 KB。发布端与订阅端都要（容器内路径）：

```bash
export FASTRTPS_DEFAULT_PROFILES_FILE=/thinker/sim/robot_sim/config/fastdds/fastdds_shm.xml
```

容器的 `tools/sim/env.sh` 已默认导出；自己写订阅脚本时别忘了，否则表现为帧率骤降或丢帧。

## 9. 排障

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `make sim-*` 报“容器未运行” | 容器没起/已退出 | `make sim-up`；`docker ps -a` 看退出码 |
| 没有 `/manip/base_pose`、相机无话题 | 桥没起或启动失败 | `make sim-logs` 看 `/tmp/sim_bridge.log`；确认 `make sim-build` 成功 |
| host 启动即退出 | 配置路径/构建产物缺失 | 用 `make sim-host`（会自动 source `.colcon-sim`）；看 `/tmp/thinker_host.log` |
| 技能出现在 `skipped` | 能力不在 robosim 变体内 | 核对 `capabilities.yaml` 与技能 `requires`；仿真缺 `body.base` 等 |
| 宿主 rqt 无图像 | Humble ↔ Jazzy 数据面不通 | 改用 `make sim-image-view`（§8） |
| 容器内图像帧率低/丢帧 | SHM 段太小 | 确认 `FASTRTPS_DEFAULT_PROFILES_FILE` 已导出 |
| 界面打不开 | 端口占用/容器未起 | 报错会提示端口占用；`SIM_VIEW_PORT=8091 make sim-image-view` |
| 仿真里站不起来/倾倒 | 未进 HBWALK、吊带高度不合适 | 按 §4.2 序列进 HBWALK；调 `SIM_HANG_Z` |
| 改技能后行为没变 | host 无热加载 | 重启 `make sim-host` |

## 10. 已知限制

- `/…/cmd` 只按 mode 0/1 的位置 / 力位混合语义执行；`cur`、`joint_ids` 与 mode 2/3/4/5 不模拟，HBWALK 下 `/leg/cmd` 忽略。
- `/robot_state` 温度固定 25 ℃、`mos_temperature` 同值，IMU 协方差全 0；真机这些是实测值。
- 自带 `ros2_bridge_msgs` 是 dex.md 的复制副本；与厂商 SDK 的同名包可能随版本漂移，SDK 可用时以其为准。
- 相机只开头部一路，腰部相机在 `interfaces.yaml` 中被注释；需要时取消注释并重建。
- 接触力估计读 `qfrc_constraint` 但峰值为 0；门/旋钮场景未建；双臂协同约束未实现。
- 平衡完全依赖厂商 FSM，静态 PD 会在 2~3 秒内倒下。
- 仿真不参与默认 `make build`；子模块在 `sim/robot_sim`，升级前先确认厂商镜像与 Fast DDS 版本（**不要**升级 `fastcdr`/`fastrtps`）。
