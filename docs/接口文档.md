## 1. 概览

本库对外提供两条正式接口 + 一条调试通道，全部指向同一个执行内核 `skill_runtime.execute()`。

| 通道 | 地址 | 适用 |
|---|---|---|
| MCP | `http://<host>:<port>/mcp`（聚合器默认 8000） | LLM Agent、跨语言调用、需要工具自描述 |
| ROS Action | `/thinker/skill/<skill>/action` | 需要阶段反馈、取消、抢占 |
| ROS Service | `/thinker/skill/<skill>/command` | 现场调试、快速验证 |

MCP 与 ROS Action 都是**通用接口**，不绑定调用方，按调用语义需求选择：

| 维度 | MCP | ROS Action |
|---|---|---|
| 消费者 | 任意 MCP 客户端：Agent、编排器、外部系统 | 任意 ROS2 节点：行为树、调度器、调试工具 |
| 发现 | 工具自描述（Schema + 描述） | ROS 图自描述（`ros2 action list`） |
| 跨网络 / 跨语言 | 好（HTTP，多语言 SDK） | 限 ROS2 环境 |
| 进度反馈 | `progress` notification，客户端支持度不一 | 原生 `feedback`，必送达 |
| 取消 | `notifications/cancelled`，取决于客户端 | 原生 `cancel`，任何客户端都会用 |
| 抢占 | 无协议语义，靠业务约定 | 原生 goal 抢占 |
| 时限 | 受客户端 read timeout（现网 300s） | 无硬上限，由技能 `timeout` 兜底 |

选型：要进度、取消、抢占选 Action；要自描述与跨语言选 MCP；两者都要时同一技能同时开放（`skill.yaml.interfaces`）。

命名规则：

```
节点     /thinker/skill/<skill>
Action   /thinker/skill/<skill>/action
Service  /thinker/skill/<skill>/command
工具名    <skill>            # MCP 工具名与技能名一致
```

## 2. 统一信封

新增技能不改协议，只加命令名 —— 这是参考实现最有价值的设计，予以保留。

在此基础上扩展两个字段，使返回值同时满足「LLM 可读」与「程序可判」：

```
ROS Service  thinker/ControlCommand
  请求 {"command": "<命令名>", "params": {...}}      # key 必须恰好是这两个
  响应 {"state": "...", "code": "...", "msg": "...", "retryable": bool, "data": {...}}

MCP Tool     tool 名 = 技能名，参数即 params 的具名展开
ROS Action   goal = {skill, params_json}
             result = {state, code, msg, retryable, data_json}
```

| 字段 | 取值 | 消费者 |
|---|---|---|
| `state` | `succeed` / `failed` / `cancelled` | 两者 |
| `code` | 大写蛇形枚举，见 §8；成功为 `OK` | **程序**（分支、重试、统计、告警分级） |
| `msg` | 中文人话，按 `code` 从配置模板生成 | **LLM / TTS** |
| `retryable` | 布尔，仅 `failed` 时有意义 | **程序**（决定是否自动重试） |
| `data` | 业务附加字段（`object_name`、`obj_pose` 等统一收进来） | 两者 |

> 不设 `category` 字段：类别由 `code` 前缀派生（`PERCEPTION_` / `MOTION_` / `NAV_` / `PRECOND_` / `SAFETY_` / `SYS_` / `INPUT_`），用命名约定避免冗余字段与不一致风险。

## 3. MCP 接口

- 工具名 = 技能名（`fetch_object`），一个技能通常只暴露 1 个工具
- 参数尽量少、优先字符串/枚举；`objPose` 这类"看起来有用但实际不生效"的参数不暴露
- **docstring 即 prompt**，必须写全：功能一句话、`Args` 含义与取值示例、`Returns` 结构、安全警告
- 服务端：`mcp.run(transport="streamable-http", host=<可配置，默认 "localhost">, port=<skill.yaml.mcp.port>)`；对外暴露需显式设 `host` 并前置反代 + 白名单
- 框架统一用 **第三方 `fastmcp`**（`from fastmcp import FastMCP`），禁止 `mcp.server.fastmcp`；服务端声明 `fastmcp>=2.12.3,<4`（按 Python 版本自适应：Humble/Py3.10 装 2.x、Jazzy/Py3.12 装 3.x），与大脑侧 `fastmcp==3.3.1` 仅保证协议兼容
- 返回值必须是 `{"state", "code", "msg", "retryable", "data"}`（见 §2），`Returns` 段要写明失败时可能出现的 `code`
- **必须处理请求取消**：客户端发 `notifications/cancelled` 时立即映射为软急停，返回 `cancelled`。工作流编排器同样会经 MCP 调用，不能假设只有 LLM Agent 在用
- 不支持取消通知的客户端（如 `langchain-mcp-adapters`）由超时看门狗兜底，见第 6 章

MCP 客户端对接配置（以 kaiwu-agent 为例，`kaiwu.yaml` 的 `work_graph_creator.mcp_cfg`）：

```yaml
mcp_cfg:
  thinker_skills:                     # 推荐：接聚合器，技能增删不改这里
    url: http://<robot-ip>:8000/mcp   # 必须带 /mcp 后缀
    transport: streamable_http        # 客户端写下划线，服务端写短横线
    sse_read_timeout: 300             # 单次工具调用上限，技能 timeout 必须小于它
```

> MCP 客户端不支持热加载：新增技能需改配置并重启进程。因此**对外只暴露一个聚合端口**，技能增删只重启聚合器；每技能独立端口（8022+）只用于技能平台注册。工作流编排器接同样的聚合端口，无需感知机器人上装了哪些技能。

`metadata.json` 关键字段：

```json
{
  "skillDefinition": {
    "name": "fetch_object", "version": "1.0",
    "description": "根据感知位姿抓取目标物体到预备位",
    "tags": ["操作类", "抓取"], "invokeType": "module",
    "modulePath": "fetch_object/mcp_interface/mcp_interface.py",
    "functionNames": ["fetch_object"]
  },
  "expand": {
    "entryPoint": "start_server", "transport": "streamable-http",
    "host": "localhost", "port": 8023, "tools": ["fetch_object"]
  }
}
```

## 4. ROS Action

```
# Goal
string skill            # 技能名
string params_json      # 参数 JSON 对象

---
# Result
string state            # succeed | failed | cancelled
string msg              # 面向 LLM 的中文可读结论
string data_json        # 业务附加字段 JSON

---
# Feedback
string phase            # 当前阶段，如 "接近" / "抓取" / "回收"
float32 progress        # 0.0 ~ 1.0
string msg              # 人类可读补充
```

语义约定：

- `phase` 取自 `Step.name`（见《Thinker-Skill 详细设计文档》4.3），与步骤一一对应，不需要技能自行维护阶段名
- cancel 立即触发软急停，等本体停稳后返回 `state=cancelled`
- 同一技能的新 goal 默认排队；运控类技能可通过 `preempt` 抢占（旧 goal 返回 `cancelled`）
- Action 的 `cancel`/`preempt` 是**协议原生语义，任何 ROS2 客户端都会用**；MCP 的取消依赖客户端是否发送 `notifications/cancelled`，因此需要抢占或确定性取消的场景应走 Action

> `Skill.action` 是**通用型**接口（goal 里带技能名），不是每技能一个类型 —— 与参考三包"新增技能不改协议、只加命令名"的思路一致。代价是编排侧看不到类型化字段，需要靠 `skill.yaml` 的 `commands` 做静态校验。

## 5. ROS Service（调试通道）

保留 `thinker/ControlCommand`（`json_request` / `json_response`）作为调试与旧链路兼容通道，与 Action、MCP 共用同一个 `skill_runtime.execute()`。不承担产品接口职责。

## 6. 一致性约束

| 约束 | 说明 |
|---|---|
| 单一出口 | 三条通道都调 `skill_runtime.execute()`，禁止在适配层另写执行逻辑 |
| 结构同构 | `state` / `code` / `msg` / `retryable` / `data` 语义完全一致，只有序列化形式不同（dict vs JSON 字符串） |
| 超时嵌套 | `skill.timeout` < MCP 客户端 read timeout（现网 300s），否则调用方先判失败而身体仍在动 |
| 孤儿任务回收 | 客户端超时断开后无法通知服务端，`skill_runtime` 必须有看门狗：**仅对持身体租约的技能**，持租约超过 `实际超时 × 1.2` 自动软急停并释放身体，否则 `body_arbiter` 被长期占用，后续调用全部被拒（实际超时见 D-009） |
| 取消三路归一 | Action `cancel`、MCP `notifications/cancelled`、看门狗超时，三者走**同一条软急停路径**，保证行为一致 |
| 命名空间隔离 | 每个技能固定 `/thinker/skill/<skill>/{command,action}`，装 N 个技能零冲突（参考实现三包同名互杀的反面） |
| 暴露面一致 | 同一技能的 MCP 工具集合与 Action 可用性由 `skill.yaml.interfaces` 单一来源决定，不允许某个通道多出能力 |

## 7. 技能接口清单

团队协作时以本节为准：每个技能上线前必须在此登记工具名、参数与错误码。

### 7.1 登记模板

| 项 | 说明 |
|---|---|
| 工具名 | 与技能名一致 |
| 参数 | 名称 / 类型 / 必填 / 默认值 / 说明 |
| 返回 `data` | 业务字段 |
| 可能返回的 `code` | 见第 8 章 |
| 超时 | `skill.yaml` 的 `timeout` |

### 7.2 `fetch_object`

| 项 | 内容 |
|---|---|
| 工具名 | `fetch_object` |
| 命令 | `fetch_bottle` |
| Action | `/thinker/skill/fetch_object/action` |
| 超时 | 120s（可选；走 MCP 时须小于客户端 300s，见 D-009） |

参数：

| 名称 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `object_name` | string | 否 | `bottle` | 目标物体名称，如 `bottle` / `can` / `plush toy` |

返回 `data`：`object_name`、`obj_pose`（如有）。

可能返回的 `code`：`PERCEPTION_OBJECT_NOT_FOUND`、`PERCEPTION_TIMEOUT`、`PRECOND_BODY_BUSY`、`MOTION_GRASP_FAILED`、`MOTION_TIMEOUT`、`SAFETY_ESTOP_TRIGGERED`、`SYS_TIMEOUT`。

`feedback.phase` 序列：`感知定位 → 接近 → 抓取 → 回收`。

> 尚未实现，随 M2 一起补齐并更新本节。

## 8. 错误码

### 8.1 生成方式

技能实现**只产出 `code`，不手拼 `msg`**：

```
技能抛/返回 code  ──▶ skill_runtime 统一出口
                        ├ code  → 原样返回（程序可判）
                        └ code  → errors.yaml 模板 + msg_params → msg（LLM 可读）
```

好处：文案可随时改、可多语言，`code` 保持稳定；参考实现里 `return_msgs.*` 是命令名做 key，改名为 `code` 做 key 后二者合流。

同时遵守**失败不抛异常**：技能内部异常必须在 `skill_runtime` 出口收敛为 `{state: failed, code: SYS_INTERNAL_ERROR, msg}`，不向调用方泄漏异常栈。

全局错误码表放 `configs/errors.yaml`：

```yaml
PERCEPTION_OBJECT_NOT_FOUND:
  msg: "没有找到{object_name}"
  retryable: true
SAFETY_ESTOP_TRIGGERED:
  msg: "急停已触发，请检查现场后复位"
  retryable: false
```

> 完整错误码枚举见附录 A。

### 8.2 消费方约定

| 消费方 | 用法 |
|---|---|
| LLM Agent | 只读 `msg`；`code` 出现在 docstring 的 `Returns` 中，帮助它判断是否值得重试 |
| 程序编排 | 只读 `state` / `code` / `retryable`，禁止匹配 `msg` |
| 监控告警 | 按 `code` 前缀做分类统计 |
| 现场调试 | 看 `code` 定位环节，看 `msg` 转述给用户 |

## 附录 A 错误码全表

> 与 `configs/errors.yaml` 一一对应，由 `tests/test_error_codes.py` 校验一致性。

前缀即类别，不额外设 `category` 字段。

| code | 场景 | retryable |
|---|---|---|
| `OK` | 成功 | — |
| **PERCEPTION_** 感知 | | |
| `PERCEPTION_OBJECT_NOT_FOUND` | 未检测到目标物体 | true |
| `PERCEPTION_TIMEOUT` | 等待感知结果超时 | true |
| `PERCEPTION_UNAVAILABLE` | 感知服务未启动 / 相机掉线 | true |
| `PERCEPTION_POSE_INVALID` | 位姿超出有效空间或数值异常 | false |
| **MOTION_** 运控 | | |
| `MOTION_GRASP_FAILED` | 力/指判断未抓到 | true |
| `MOTION_IK_UNREACHABLE` | 目标位姿不可达 | false |
| `MOTION_TIMEOUT` | 动作链超时 | true |
| `MOTION_COLLISION_RISK` | 规划判定碰撞 | false |
| `MOTION_NOT_READY` | 控制器未初始化 / 未回零 | true |
| **NAV_** 导航 | | |
| `NAV_TARGET_UNREACHABLE` | 目标点不可达 / 被占用 | true |
| `NAV_TIMEOUT` | 导航超时 | true |
| `NAV_MAP_NOT_READY` | 未建图 / 未定位 | false |
| `NAV_LOCATION_LOST` | 运行中丢失定位 | true |
| **PRECOND_** 前置状态 | | |
| `PRECOND_NOT_HOLDING` | 手上没有物体（如放置前未抓取） | false |
| `PRECOND_ALREADY_HOLDING` | 已持物，拒绝再次抓取 | false |
| `PRECOND_BODY_BUSY` | 身体被其他技能占用 | true |
| `PRECOND_CAPABILITY_MISSING` | 所需能力未安装（缺技能/缺硬件） | false |
| **SAFETY_** 安全 | | |
| `SAFETY_ESTOP_TRIGGERED` | 软/硬急停触发 | false |
| `SAFETY_FORCE_LIMIT` | 力超阈值 | false |
| `SAFETY_STUCK_DETECTED` | 卡死保护触发 | false |
| `SAFETY_SPACE_VIOLATION` | 目标超出安全工作空间 | false |
| **INPUT_** 输入 | | |
| `INPUT_INVALID_PARAMS` | 参数缺失 / 类型错误 | false |
| `INPUT_UNSUPPORTED_COMMAND` | 命令不在白名单 | false |
| **SYS_** 系统 | | |
| `SYS_CANCELLED` | 被取消（`state=cancelled` 时使用） | false |
| `SYS_TIMEOUT` | 技能级超时（看门狗） | true |
| `SYS_INTERNAL_ERROR` | 未预期异常（已收敛，不泄漏栈） | true |
| `SYS_DEPENDENCY_MISSING` | 依赖包/权重缺失 | false |
| `SYS_CONFIG_ERROR` | 配置项缺失或非法 | false |

命名规则：

- 全大写蛇形，**必须带类别前缀**，前缀取上表七类之一
- 一个 code 只描述**一种失败原因**，不允许 `MOTION_ERROR` 这类大而全的码
- 新增 code 必须同时更新 `configs/errors.yaml` 与本表，否则 `tests/test_error_codes.py` 失败

## 附录 B 兼容性策略

| 类别 | 内容 |
|---|---|
| **稳定**（不可随意改） | MCP 工具名、参数名与语义；Action `goal` / `result` 字段语义；错误码取值；命名空间 `/thinker/skill/<skill>/…` |
| **可演进**（允许追加） | Action / Service 消息追加字段（调用方须忽略未知字段）；错误码前缀内新增取值；`feedback` 追加字段 |
| **破坏性变更流程** | 新增工具名与旧名并存一个版本 → 文档标记「已弃用」→ 下个主版本移除 |

调用方约束：必须忽略未知字段，不得依赖 `msg` 文案内容做逻辑判断。
