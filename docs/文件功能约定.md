## 1. 总则

1. **一个文件一个写者**：同一时刻只有一个人改一个文件；需要别人改，提需求，不直接动手。
2. **契约先行**：方法签名、数据结构字段、配置键、错误码四类属于契约，改动必须先落决策（D-0xx）再改代码。
3. **只读引用要声明**：跨模块调用只允许通过下表列出的接口，禁止 import 对方内部模块。
4. **冻结日优先于“顺手改”**：冻结后发现的缺口走单开小 MR，不夹在功能 MR 里。

## 3. 契约清单

### 3.1 SDK 协议（现役 + 本期新增）

| 协议 | 现役方法 | 本期新增 |
|---|---|---|
| `ArmAPI` | `move_to_joints / get_joints / is_moving / move_to_pose(pose, tcp=) / get_tcp_pose / is_reachable` | `move_linear / follow_path / set_speed_scale / push_until` |
| `GripperAPI` | `grasp / release / set_positions / get_positions / is_holding` | 无（通道语义放 `hand.py`） |
| `BodyAPI` | `arm / arms / gripper / grippers / waist / head / base` | 无（双手机已具备） |
| `SensorAPI` | `rgbd / transform_to_base` | `rgbd(camera=) / ir_frame / pose_snapshot / ft` |

约定：
- `Pose` 的四元数是 **xyzw**；全 0 视为非单位四元数，走 6D 求解；单位四元数只约束位置。
- `move_to_pose` 必须幂等，允许每 tick 重复下发同一位姿。
- 可选能力（位姿 IK、力、红外、点云）不得写进技能的 `requires`，用运行时探测 + 兜底。

### 3.2 数据结构

| 结构 | 字段 | 约束 |
|---|---|---|
| `GraspSpec` | `type, mode, pose_base, frame, width_m, width_min, width_max, force_target, approach_dist_m, contact_points, score_breakdown` | 位姿在 base 系；`type ∈ {pinch, power, press}` |
| `GripperInfo` | `channels, width_range_m, presets, supports` | `channels ∈ {flex, thumb_opposition, spread}` |
| `TargetRecord` | `source, pose_base, frame, obb?, press_face?, axis?, hinge_axis?, stamp, pose_snapshot, mask_ref?` | `source ∈ {teach, vision}` |
| `IrFrame` | `data, stamp, side, camera` | 无效像素 0xFFFF |
| 分割结果 | 12 字段（见 `dev-b` §4） | `mask_ref` 走路径不进信封 |

### 3.3 能力与版本

- `capabilities.yaml` 的 `version` 由 A 维护：3.0 → 3.1（只加键，不改旧值）。
- 新能力用新键表达（如 `body.arm.pose_ik_6d`），**不要修改已有键的语义或类型**（`load_capabilities` 只把键当集合用）。
- `backend_variants.robosim.remove` 由 A 维护；测试期跳过用 `tests/sim_skip.yaml`，不写进能力文件。

### 3.4 错误码一致性（四处）

| 位置 | 责任 |
|---|---|
| `ErrorCode` 常量类 | A |
| `configs/errors.yaml` | A |
| `configs/sim/errors.yaml` | A（逐字节一致） |
| `docs/接口文档.md` 附录 A | A |

新增码必须有 `msg` 与 `retryable`；未注册码在 `ErrorCatalog.render` 里会退化为空文案、`retryable=False`，所以 `tests/test_error_codes.py` 必须过。

### 3.5 配置加载

- 入口 `configs/main.yaml` → `includes: [robot.yaml, targets/*.yaml ×3]`，深合并（`_deep_merge`）。
- 目标库顶层写 `skills:`，合并后落在 `skills.<skill>.targets`。
- 技能私有参数只放 `configs/robot.yaml` 的 `skills.<名>` 段，经 `ctx.cfg` 注入。
- 配置在 host 启动时加载，改完重启（无热加载）。

## 9. 名词解释

### 9.1 运行模型

| 术语 | 代码名 | 定义 |
|---|---|---|
| 技能 | Skill | 可被 MCP 或 ROS Action 调用的能力单元；目录 = ament 包 + `mcp_interface/` |
| 插件 | Plugin | 技能实现类，实现 `build_steps(ctx, params) -> list[Step]` |
| 步骤 | Step | 每 tick 调用一次的单元，返回 `running / done / failed`；带 `weight`、`timeout`、`tick_budget` |
| tick | — | 10 Hz 主循环，一次 0.1 s |
| tick 预算 | `tick_budget` | 单次 `run` 的最长耗时（默认 0.1 s）；超了告警不中断 |
| 租约 | Lease | `body_arbiter` 的区域占用，区域为 `head / upper / lower`；技能执行期持有 |
| 抢占 | preempt | 更高优先级任务收回租约，持有方须在安全点停机 |
| 信封 | Envelope | 统一返回结构 `{state, code, msg, retryable, data}` |
| 四路径 | — | 每个技能的四种终态：成功、业务失败、超时、取消 |
| 业务失败 | `retryable=false` | 重试不会变好的失败（如目标不存在、邻键过近） |
| 能力 | capability | `capabilities.yaml` 里的键，装配期与技能 `requires` 做子集匹配 |
| 状态快照 | `pose_snapshot` | 某一时刻的腰/头/臂关节角 + stamp，用于把像素正确投到 base |

### 9.2 几何与抓取

| 术语 | 代码名 | 定义 |
|---|---|---|
| base 系 | `frame="base"` | 以 pelvis 为原点、按 `pelvis_height` 折算到地面；全仓库默认坐标 |
| TCP | `tcp=True` | 工具中心点；`move_to_pose(tcp=True)` 时位姿指抓取中心而非腕部 |
| 预接触位 | pregrasp | 目标沿接近轴后退 `approach_dist` 的位置 |
| 接近轴 | approach（z） | 手掌朝目标的轴；姿态第一列 |
| 闭合轴 | closing（x） | 两指连线方向；捏合要横跨物体短轴 |
| 主法向 | `normal` | 点云 PCA 最小特征值方向，朝相机侧翻转 |
| 副主轴 | — | OBB 的次长轴，判断闭合轴对齐用 |
| OBB | `obb` | 有向包围盒：`center / quat(xyzw) / half_extents` |
| 门轴 | `hinge_axis` | 门板平面与竖直棱边的交线；关门态不可由两平面交线观测 |
| 合手 | squeeze | 从预设张开位闭合到接触并保持的过程 |
| 滑脱 | slip | 位置回退超阈或电流塌陷，判定为抓空或掉件 |
| 卡阻 | blocked / stuck | 力或电流持续超限，判定为撞到障碍 |
| 先验 | prior | 目标库里上一次的位姿，运行期只作搜索种子 |
| 重定位 | relocate | 在先验 ±5 cm 窗内重新拟合，偏差超阈报目标丢失 |

### 9.3 目标与校准

| 术语 | 代码名 | 定义 |
|---|---|---|
| 目标 | `TargetRecord` | 一个可操作对象：`source` + 位姿/几何 + stamp + 快照 |
| 示教 | `source: teach` | 用 `record_teach_pose.py` 读当前关节角算出的位姿 |
| 视觉 | `source: vision` | 掩码 + 几何拟合得到的位置、朝向、尺度 |
| 目标库 | `configs/targets/*.yaml` | 技能的私有目标配置，按技能一文件 |
| 冻结日 | — | 某类契约停止变更的日期，之后只走小 MR |
| TCP 标定 | — | 六点法求夹爪抓取中心相对腕部的偏置 |
| 手眼标定 | AX=XB | 求相机相对末端的变换；20 组位姿最小二乘 |

### 9.4 协作与验收

| 术语 | 定义 |
|---|---|
| 单写者 | 一个文件同一时刻只有一个人改，见 §2 |
| 只读引用 | 只 import 不改；需要新能力提给写者 |
| 技术债登记 | 明知两处实现并存时，写进风险表并定统一时间，不默认遗忘 |
| 契约变更 | 方法签名、字段、配置键、错误码四类，需 D-0xx + 文档同步 |
| 仿真跳过 | `tests/sim_skip.yaml`，测试期声明，不是机型能力 |
| 台架记录 | `docs/验收/<主题>.md`，含日期、参数、原始数据路径 |

## 10. 约束

### 10.1 硬约束（不可协商）

| 约束 | 事实 | 证据 | 影响 |
|---|---|---|---|
| 控制周期 | 10 Hz，单步 0.1 s | `pipeline.py:63`、`step.py:40` | 超 100 ms 的算法必须拆成多 tick 或独立 step |
| 臂接口 | 7 DOF，只有关节位置；`duration` 被丢弃 | `body.py:203-206` | 速度控制只能靠执行器重采样 |
| 位姿能力 | 6D IK 已具备，含 TCP 口径 | `ik.py:82-197`、`body.py:244-317` | 可直接下发姿态，无需再改 IK |
| 手接口 | 0..1 归一化开合；无独立力矩指令 | `GripperAPI`、`inspire_hand.py` | 抓握只能靠位置 + 电流/触觉判据 |
| 触觉 | 仅 inspire 指尖 `contact_state`（0.01 N） | `fetch_object/plugin.py` | 无六维力，按压/握持需兜底路径 |
| 点云 | `sensor.pointcloud` 只声明无实现 | `capabilities.yaml` | 分割必须自己从深度反投影 |
| 相机 | 4 个命名空间，单套内参 | `sensor.py:16-19` | 腕相机外参需自标，未标前不能用于操作 |
| 平台 | Jetson aarch64；无 scipy/open3d，cv2 仅仿真工具用 | 仓库依赖现状 | 几何算法用 numpy 手写 |
| 系统 | ROS 2 Humble 与 Jazzy 双版本 | `plan.md` | 不做 ABI 级 C++ 插件 |
| 单位 | 长度 m（字段名带 `_mm` 时用 mm）；力 N；角度对外 °；四元数 xyzw | §5 | 跨模块传参不做隐式换算 |

### 10.2 开发约束（必须遵守）

| 约束 | 说明 | 违反后果 |
|---|---|---|
| 不改 `core/skill_core` | 本期对 pipeline / host / arbiter 零改动 | 影响全部技能，需评审并单独排期 |
| 可选能力不进 `requires` | 位姿、力、红外、点云一律运行时探测 + 兜底 | 仿真会整技能 skip，六技能冒烟不成立 |
| 阈值单一来源 | 数值只在 §5 类规格表里定义，卡片与代码引用 | 改一处漏一处，回归随机红 |
| 禁止跨技能 import | 技能之间只经 `ctx.call_skill` 或公共模块 | 部署时缺依赖、循环引用 |
| 契约变更四件套 | D-0xx + 四份主文档 + `DESIGN.md` + 版本号 | 代码与文档分叉，验收口径失效 |
| 依赖必须声明 | 新库写进对应包 `install_requires` | 装到机器人上才炸 |
| 单写者 | 见 §2 的“写者”列 | 并行期互相覆盖 |
| 冻结后单开 MR | 冻结日之后的缺口不夹带 | 冻结日形同虚设 |

### 10.3 优先级

文档 > 配置 > 代码常量；同一层冲突以《决策记录》为准（与 `CODEBUDDY.md` 的约定一致）。配置里的技能段只能覆盖本技能，不能改全局语义。

### 10.4 红线（违反直接打回）

1. 未在 `install_requires` 声明就引入第三方库。
2. 把可选能力（力、红外、点云、位姿）写进技能 `requires`。
3. 在技能内复制 SDK 或公共模块已有的能力（IK、几何、抓取候选）。
4. 绕过评审改 `core/skill_core` 或 `capabilities.yaml`。
5. 没过四路径就声称“技能可用”。
